# 04 Competitor Positioning Card

## Use When

Use after the priority competitor pool is confirmed, especially before differentiation analysis.

## Goal

Understand how each competitor defines itself, who it sells to, what result it promises, and what proof or objection-handling it uses.

## Depth By Type

| Competitor Type | Scan Depth |
|---|---|
| Direct | Homepage, features, use cases, pricing, comparison/alternatives, FAQ, demo/onboarding if visible |
| Indirect | Only pages related to the shared problem, substitute path, or relevant workflow |
| Aspirational | Homepage, templates, resources, customer stories, creator/community pages, campaign pages |

## Steps

1. Read official pages first.
2. Capture the homepage headline or one-line positioning.
3. Extract repeated selling points, target users, scenarios, proof, pricing/CTA, and comparison targets.
4. Mark potential differences vs the product as hypotheses, not conclusions.

## Deliverable

| Field | Output |
|---|---|
| Competitor | Name and URL |
| One-line positioning | Their own wording or close paraphrase |
| Core selling points | 3-5 repeated claims |
| Target users | Roles, teams, personas, buyer/user split |
| Use cases | Concrete scenarios |
| Trust proof | Logos, ratings, reviews, metrics, cases, awards |
| Objection handling | Privacy, security, price, accuracy, ease, proof |
| Pricing/CTA signal | Free/trial/freemium/paid/demo/signup |
| Comparison objects | Products named in vs/alternative pages |
| Potential difference vs product | Early hypothesis |
| Source links | URLs used |
