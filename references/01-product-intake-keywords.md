# 01 Product Intake And Initial Keywords

## Use When

Use when product context is missing, weak, or only described in marketing language. This scenario must happen before competitor discovery unless the user already provides a clear product brief.

## Goal

Create enough product understanding to discover relevant competitors without overfitting to later differentiation claims.

## Inputs

- Product name and official website/app listing.
- Existing positioning or user-provided description.
- Target market, language, and platform focus when available.
- Known competitors or substitute tools when available.

## Steps

1. Read official website, app/store listing, docs, pricing, landing page, or launch page.
2. Extract what the product does, who it serves, where it is used, and why users care.
3. Identify user pain in user language, not only feature language.
4. Generate initial keywords for competitor discovery.
5. Converge keywords: keep terms likely to reveal competitors or substitutes; defer overly broad social exploration terms.

## Keyword Sources

| Source | Keyword Type | Example |
|---|---|---|
| Product functions | Category/function words | AI meeting notes, transcription tool |
| User problems | Pain words | too many meetings, manual notes |
| Use cases | Scenario words | sales call notes, lecture summary |
| Target users | Persona words | tools for students, tools for founders |
| Known competitors | Competitor/alternative words | [competitor] alternative |
| Platform habits | Native phrasing | best [category] tools, how to [task] |

## Deliverable

| Field | Output |
|---|---|
| Product positioning | One clear sentence |
| Target users | Primary and secondary personas |
| Use cases | 3-6 concrete scenarios |
| Pain points | 3-6 real user problems |
| Core selling points | 3-5 benefits/capabilities |
| Known competitors/substitutes | Names and source |
| Initial keyword map | Category, pain, scenario, persona, competitor, platform phrasing |
| Assumptions | What was inferred and needs validation |
